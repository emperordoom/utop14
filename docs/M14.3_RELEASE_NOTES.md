## Scope Delivered in M14.3 (PR #14)

### 1. Login Rate Limiting and Authentication Abuse Protection
- Introduced PostgreSQL-backed fixed-window rate-limiting persistence (`auth_rate_limits`, migration `e1b7c4a9d2f3`) and service logic (`app/services/auth_rate_limit.py`) supporting identifier, IP, and combined windows, configurable thresholds, cooldowns, and TTL policy.
- Wired login abuse controls into authentication routes (`app/services/login_abuse.py`, `app/auth/routes.py`, migration `b4d8e2f7a1c9` adding the throttled login security event type, and HTTP `429` enforcement).
- Added the bounded CLI maintenance command (`flask --app wsgi auth-rate-limit cleanup`) and unit/integration test suites covering rate-limit keys, cooldown escalation, and migration integrity. (No CLI inspection command was added by PR #14; diagnostic commands such as `check-clock` and `orphans` were introduced later in PR #16.)

### 2. Security Event Retention
- Added security-event retention holds and run-log tables (`app/models/security_event_retention.py`, migrations `d7c1a9e4b2f8` and `e3b9f1c7a2d4`), bounded retention pruning logic (`app/services/security_event_retention.py`), and the manual execution CLI command (`flask --app wsgi security-event-retention run`).
- Isolated pruning into a `SECURITY DEFINER` PostgreSQL function owned by `utop14_retention_owner` (`NOLOGIN`) and executable only by `utop14_retention_runner` (`LOGIN`), with hold-lock enforcement and concurrency tests.

### 3. Least-Privilege Database Ownership and Verification
- Added the DBA review-and-adapt ownership template (`scripts/security_event_retention_ownership_template.sql`), repeatable transactional role provisioning (`scripts/security_event_retention_roles.sql`), and superuser verification script (`scripts/security_event_retention_verify.sql`).
- Enforced least-privilege DML-only access for `utop14_app`, default-deny recursive role memberships, default-deny parameter ACLs, cross-database persistent GUC allowlists, sensitive `postgresql.auto.conf` checks, and full `pg_catalog.` qualification guarded by a live-catalog static regression test (`tests/integration/test_security_catalog_qualification.py`).
